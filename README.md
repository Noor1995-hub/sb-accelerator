# Second Brain Accelerator

Product monorepo for the **Second Brain Accelerator**: a personal AI operating
system for a client executive — the vault owner — deployed by delaware
consultants inside AI transformation engagements and maintained as a
versioned product.

Engineering conventions and the bootstrap rationale:
`docs/superpowers/specs/2026-08-22-sb-accelerator-bootstrap-brief.md`.

## Structure

| Path | What it is |
|---|---|
| `plugin/` | Claude Code plugin: 14 skills and 5 agents (index: `plugin/skills/README.md`). No hooks. Ships to clients via `sb-dist`. |
| `plugin/template/` | Vault skeleton: folders, `.obsidian/`, `.base` views, CLAUDE.md + context-portfolio slots. Instantiated once per client. |
| `plugin/vendor/obsidian/` | The pinned Obsidian community plugins + Minimal theme, unmodified upstream release files, so `/provision-vault` installs them offline. Regenerated by `scripts/refresh_vendor.py` from `plugin/lib/plugin-pins.json`; never hand-edited. Licences in `LICENSES.md` there. |
| `plugin/migrations/` | Versioned structure migrations (`001`–`014`, structure versions 2–15), shipped with the plugin and applied by `/upgrade-vault`. |
| `migrations/` | Only a place to write down a migration *candidate* before it joins the chain in `plugin/migrations/`. See its README. |
| `playbooks/` | Onboarding interview, pre-flight checklist, provisioning runbook, hypercare. Never ships. |
| `docs/` | Architecture, distribution channels, backlog model, local setup, builder onboarding. |
| `registry.yaml` | Deployment registry, client and internal (v1: file; later Airtable). |
| `scripts/dist/` | The dist-tree template (`README.md.tmpl`) `scripts/build_dist.py` renders for each release channel. Never ships itself. |

## The four layers (what ships, what doesn't)

- **L0** ontology & taxonomy → ships (template)
- **L1** automation → ships (plugin), de-personalized
- **L2** delaware company knowledge → **never ships** (separate overlay, later)
- **L3** personal context → generated per user at onboarding, never in this repo

**Hard rule:** nothing in `plugin/` — which now includes the template at
`plugin/template/` — references delaware clients, Michael, or busdev content.
CI lints this (`scripts/lint_plugin.py`).
