# Daily Loop Port — Design

**Date:** 2026-08-23 · **Parent issue:** #2 · **Provenance:** `busdev@ccc27b8`

Ports the daily-loop skills from the lab vault into the plugin: recorder
transcript sync (**#14**), morning brief (**#15**), evening brief (**#16**).
Consumes the conventions settled in
`2026-08-23-object-skills-port-design.md` (deterministic CLI, compiled
ontology, surface matrix, runtime constraints) and the product design
`2026-08-22-second-brain-accelerator-design.md`.

This is a design, not a plan. These skills consume `plugin/lib/vaultlib`,
which PR P1a is building; implementation planning happens after P1a merges.

## Source mapping (verified against the lab vault, not assumed)

| Issue | Lab source | Notes |
|---|---|---|
| #14 | `sync-plaud` (512 L) + `99-workflow-config/plaud/sync-helper.py` (~660 L, tested) | Deterministic layer lives outside the skill dir upstream; `calibration.py` measures the auto-confirm gate |
| #15 | `morning-brief` (707 L) | Renders BOTH briefs via `--evening`; also writes a `Today.md` sidecar and the daily-note skeleton |
| #16 | `evening-sync` (337 L) + `lib/build_update_queue.py` (702 L) | Nightly maintenance job: sync → project-state refresh → decision graph → calls `morning-brief --evening` |

Facts that reframe the port, verified in the lab vault:

- **`migrate_decisions.py` (859 L) is not runtime.** It is the one-shot,
  idempotent 2026-05-15 migration of inline decision bullets into atomic
  notes. It does not port; its *pattern* (deterministic migration script +
  report) is prior art for `migrations/`, nothing more.
- **Lab scheduling is no longer systemd/cron.** Both jobs run as Claude Code
  scheduled tasks on the Mac (`~/.claude/scheduled-tasks/*/SKILL.md`),
  replacing the retired GCP VM cron (2026-08-19). The live task prompts
  carry two production-learned rules ported below as critical rules:
  *unattended mode must never block on a prompt* ("exit 0, nothing done"
  failures), and *verify against disk, not the run's own narrative* (a sync
  reported "Processed: 0" while having correctly written a meeting).
- **The template already decided where daily output lands.** `CLAUDE.md`
  declares `60-daily-notes/` as the briefs' home, `daily-notes.json` points
  Obsidian's daily-note plugin there, and filenames are ISO. Upstream's
  `DD-MM-YY` brief filenames and `Today.md` sidecar have no template
  counterpart.
- **The ontology already promises auto-maintenance with no producer.**
  `meetings-7d`, `meetings-30d`, `key-people` are documented as
  auto-maintained on Project and Person; nothing in P1a/P1b writes them.
  Likewise `review_status: confirmed` is unreachable without the
  reviewed-checkbox reconciliation. Both producers land here.

## Decisions

1. **One daily artifact: the daily note.** The evening run prepares
   `60-daily-notes/{YYYY-MM-DD}.md` for the *next* day: a recap of today's
   meetings (plus cross-cutting themes when there are ≥2), then one section
   per upcoming calendar meeting carrying vault prep and an empty area for
   manual notes during the meeting. This is a deliberate redesign of the
   lab's three artifacts (brief file + `Today.md` + daily-note skeleton) —
   decided 2026-08-23 with Michael as core architecture, not drift. The
   `DD-MM-YY`-vs-ISO filename split disappears with the brief files.
2. **#15 closes as superseded.** There is no morning skill. The evening run
   is the only writer of the daily note; overnight calendar drift is
   accepted, and recovery from a missed run is invoking `/evening-sync`
   manually. Recorded here so the issue can be closed with a pointer.
3. **Stages, not skills, are the unit.** The engine is a pipeline —
   harvest · sync · reconcile · refresh · project-state update · decision
   capture · daily-note write — where deterministic stages are `vaultlib`
   subcommands and judgment stages are skill prose or sub-skill calls.
   Skills are thin entry points that select stages: `/evening-sync` runs
   the full chain; `/sync-recordings` is the capture stage standalone.
   Neither invokes the other's SKILL.md as a brief-renderer (the lab's
   "evening brief generated by morning-brief" naming accident does not
   ship).
4. **`/sync-recordings` takes a three-adapter intake.** Surfaces designed
   for, per Michael 2026-08-23 (exec-team confirmation pending on the
   connector set):
   1. `inbox` — transcript files dropped in `10-inbox/` (always available),
   2. `plaud` — the Plaud MCP connector (plugin-bundled `.mcp.json` or
      admin-provisioned; Cowork end users cannot add MCP servers
      themselves),
   3. `m365` — Teams meeting transcripts via the Microsoft 365 connector.
   Adapters do discovery + fetch only, producing a normalized **capture
   bundle** (metadata: id/title/start/duration · transcript · optional
   enrichment summary — the shape the lab's `reassemble` step already
   proves). Everything downstream is one source-agnostic pipeline.
5. **Adapter activation is configuration + capability, not code.**
   `tools-and-systems.md` (context portfolio, filled by `/setup-my-brain`)
   declares which channels a deployment uses; the skill additionally
   verifies the adapter's tools exist before running it. A missing
   connector skips that adapter with an explicit summary line — never a
   silent zero.
6. **Dedup keys are namespaced.** `source-recording-id` carries
   `plaud:{id}` / `m365:{id}` / `inbox:{content-hash}`; a content-hash
   check backstops the same recording arriving via two channels. The vault
   remains the ledger: a failed item writes nothing and retries next run.
7. **The auto-confirm gate does not ship.** It was calibrated against
   Michael's meeting population (`calibration.py`, 2026-07); a fresh client
   vault has no calibration data. Every synced meeting lands
   `needs-review`; the confirm path is the `reviewed` checkbox reconciled
   by `cli.py sync reconcile-reviews`. The `confidence` /
   `confidence-reasons` vocabulary DOES ship, written to frontmatter from
   day one, so a future calibration story has data. `review_status` keeps
   its three values — no `auto-confirmed` enum member until there is a
   producer.
8. **Harvest is read-only.** The evening run reads today's daily note —
   per-meeting jottings and end-of-day bullets become inputs to the recap
   and candidates for `/log-decision`, alongside transcripts — and never
   modifies it. The note is the archive of the day. Routing jottings
   onward (into meeting notes, open items) is deliberately out of v1:
   routing hand-scribbled fragments unattended is the highest-risk fuzzy
   write in the batch.
9. **Recap window = everything since the last daily note.** Friday's run
   writes Monday's note recapping Friday; a week's gap recaps the gap. One
   deterministic rule replaces upstream's `last_week` Sunday special case
   and its weekend-derivation bugs.
10. **Machine regions are marker-fenced; the CLI owns the merge.** Inside
    the daily note, machine-written regions sit between
    `<!-- evening-sync:{region}:begin -->` / `:end` markers (same
    convention as the context portfolio's `setup-my-brain` markers).
    `cli.py daily-note write` regenerates marked regions and is forbidden
    from touching a byte outside them. One writer class per region is the
    scalability rule the organically-grown lab vault lacked.
11. **No sidecar JSON.** Upstream's `decision-diff-latest.json` passed
    state from `evening-sync` to next morning's brief across two skills.
    Here the engine calls `/log-decision` itself and renders what came
    back in the same run. One less file format, one less staleness bug.
12. **`build_update_queue.py` ports; `--auto-fix` does not.** The queue,
    metrics, and reverse-direction self-check become
    `cli.py sync update-queue` (stdlib-only: P1a's frontmatter parser and
    compiled schema replace PyYAML). The auto-fix mutator's job — decision
    -graph drift repair — is parked toward the `/health-check` conformance
    subcommand already parked in P1a's design; v1 surfaces drift as
    warnings only.
13. **Scheduling stays out of the plugin.** Skills are schedule-agnostic
    and expose an unattended mode; how the evening run fires (Claude Code
    scheduled task on the EA machine, Cowork scheduling, or manual) is a
    per-engagement provisioning decision recorded in the playbook. No
    cron/systemd/launchd artifact ships. Upstream's
    `authoritative-dates.py` pattern survives as `cli.py dates` — the
    model never derives day-of-week arithmetic.
14. **Personal couplings resolve to the context portfolio.** Timezone from
    `identity.md` (never hardcoded Brussels); internal mail domains from
    `tools-and-systems.md` (never the delaware list); briefing preferences
    (language, depth) from `preferences-and-constraints.md`; `key-people`
    excludes the executive by their person slug (never a hardcoded name
    filter — which is also why the lab's display-name self-filter could
    not have ported). The lab's "no action items, Michael uses Todoist"
    rule genericizes to: open items live on projects, and the recap links
    them rather than duplicating a task list.

## Architecture

```
plugin/skills/
  sync-recordings/SKILL.md        # 14 — capture, standalone entry point
  evening-sync/SKILL.md           # 16 — the engine
plugin/lib/vaultlib/              # P1a foundation, extended here
  cli.py                          # new subcommand groups: sync, daily-note, dates
```

New `vaultlib` subcommands (all stdlib-only, Python 3.10 floor, vault root
always a parameter, JSON on stdout — P1a's rules):

| Subcommand | Owns |
|---|---|
| `dates` | Authoritative date block: today, next business day, recap window since last daily note. Timezone passed in from the context portfolio. |
| `sync scan` | Inbox adapter discovery + dedup of any adapter's capture list against the vault, keyed on namespaced `source-recording-id` with content-hash backstop |
| `sync reconcile-reviews` | `reviewed: true` → `review_status: confirmed` flips (from `needs-review` only, one-way; `archived` is never read) |
| `sync update-queue` | Port of `build_update_queue.py`: project/person `meetings-7d` / `meetings-30d` / `key-people` writes, the queue of projects needing state synthesis with their `existingDecisions` projection, and the reverse-direction self-check |
| `meeting write` | Schema-validated meeting note emission; collision guards; never overwrites `confirmed` (writes the `-v2` `needs-attention` sibling with `conflicts-with`) |
| `daily-note write` | Renders/regenerates the marker-fenced machine regions of a daily note; bytes outside markers are untouchable; idempotent |
| `daily-note read` | Parses a daily note into regions + human jottings as JSON, for the harvest stage |

Division of labour follows P1a: the model owns judgment (project linking,
brief prose, theme synthesis, decision candidates, routing a jotting to the
meeting it belongs to); the script owns everything mechanical (dates, dedup,
validation, metrics arithmetic, marker merges, atomic writes).

## D1 — `/sync-recordings` (#14)

```
/sync-recordings                 # interactive: show plan, confirm once, run
/sync-recordings --unattended    # no prompts (pipeline stage / scheduled)
```

1. **Resolve adapters.** Read `tools-and-systems.md` for declared channels;
   probe tool availability per adapter. Report what will run.
2. **Discover + fetch** per active adapter into capture bundles.
   - `inbox`: `cli.py sync scan` over `10-inbox/` (transcript-shaped files;
     the fixture inbox is the reference corpus).
   - `plaud`: MCP `list_files` over a scan window → `get_transcript`
     (required, 3× retry) → `get_note` (optional enrichment, degrade
     without). Raw tool results go to scratch via Write, reassembled
     deterministically — no large JSON through Bash.
   - `m365`: Teams transcript retrieval through the M365 connector.
     **Interface designed here; internals pending a verification spike on a
     real tenant** — Teams transcripts live in organizer OneDrive/
     SharePoint and the lab has no prior art for this path.
3. **Dedup** via `cli.py sync scan` (all adapters feed the same check).
4. **Calendar enrichment** when the M365 calendar tool is available.
   Ported verbatim in spirit: `calendar-tool-unavailable` ≠
   `no-calendar-match` — "couldn't look" and "looked, found nothing" are
   different facts, and conflating them once hid a six-day outage upstream.
5. **Project linking** (model judgment): entity-domain match against
   `40-entities/*/`, calendar-subject and content keywords against project
   names/slugs. Empty `projects: []` is fine — triage catches it.
6. **Confidence stamp**: rating + closed reason vocabulary (see ontology
   below) into frontmatter. No gate — everything lands `needs-review`.
7. **Interactive confirm** (skipped under `--unattended`): one table, one
   question.
8. **Extraction subagents** (parallel, pinned to a small model — structured
   extraction, not judgment): transcript-first Key Takeaways / Debrief /
   Action Items, full-name attendees, write via `cli.py meeting write`.
9. **Person auto-creation** for unknown attendees (`relationship: null`,
   surfacing as Uncurated in People.base — same convention as P1a's owner
   rule).
10. **Summary against disk**: counts come from globbing what was written,
    not from the run's narrative. Per-adapter lines, skipped adapters named.

Strip list applied (#14): Plaud-account assumptions → adapter contract;
delaware domain list → context portfolio; delaware people-management
heuristics → dropped (a generic 1:1 keyword heuristic stays, exec-neutral);
client slugs → none survive; shadow-log/calibration machinery → not ported
(the frontmatter itself is the calibration record until there is a consumer).

## D2 — `/evening-sync` (#16)

```
/evening-sync                    # interactive
/evening-sync --unattended       # scheduled shape — never prompts
```

Stages, failure-isolated (a failed stage logs and the chain continues):

1. **Dates** — `cli.py dates`; consumed verbatim, never re-derived.
2. **Harvest** — `cli.py daily-note read` on today's note: jottings per
   meeting + end-of-day bullets become recap context and `/log-decision`
   candidates. Read-only.
3. **Sync** — run the `/sync-recordings` stage `--unattended`.
4. **Reconcile** — `cli.py sync reconcile-reviews`.
5. **Refresh** — `cli.py sync update-queue`: metrics writes + the project
   queue + self-check warnings.
6. **Project-state update** — per queued project, a subagent (bounded
   parallelism) rewrites exactly the Now callout, `## Open Items`, and the
   three frontmatter fields (`last-updated`, `next-milestone`,
   `next-milestone-date`), and hands decision candidates (from meetings AND
   harvest) to `/log-decision` background mode — the #36 producer split,
   already decided. Upstream conservatism rules carry over: material-
   decision test (commits the engagement AND would change a stakeholder's
   behaviour), supersession only on explicit conflict language, never
   delete, status flips only, skip projects with no confirmed meetings.
7. **Write tomorrow's daily note** — `cli.py daily-note write` renders the
   machine regions; the model supplies recap prose, themes, and per-meeting
   prep (attendees, last-meeting one-liner, dossier context from the entity
   dossier — same lookups as upstream's Step 5, against `40-entities/` and
   `30-projects/`). Calendar unavailable → note still written: recap +
   an explicit "calendar unavailable" line in the Meetings region.
8. **Verify against disk, then summarize** — tomorrow's note exists with a
   fresh mtime; every project reported updated shows a bumped
   `last-updated`; every recording reported synced exists in
   `20-meetings/`. The summary renders decision-capture results from step 6
   directly (no sidecar). Self-check warnings surface verbatim.

## The daily note contract

`60-daily-notes/{YYYY-MM-DD}.md`, one per working day, written the evening
before, jotted in during the day, harvested that evening:

```markdown
---
date: {YYYY-MM-DD}
type: daily-note
---

# {YYYY-MM-DD} · {DayName}

## Recap
<!-- evening-sync:recap:begin -->
> [!info] At a glance
> {window summary — N meetings · entities · themes}
{per-meeting takeaway bullets · decisions logged · watch items}
<!-- evening-sync:recap:end -->

## Meetings

### {HH:MM} — {Subject}{ · [[entity-slug]]}
<!-- evening-sync:prep:begin -->
**Attendees:** … · **Last meeting:** {date — one line} · **Context:** {dossier}
<!-- evening-sync:prep:end -->
- 

## End of day
- 
```

Rules: machine regions regenerate wholesale on any re-run; human text —
jotting bullets under each meeting, `## End of day`, anything else — is
untouchable. `## Meetings` with an empty calendar renders
`*No meetings scheduled.*` inside a prep region. Times in the executive's
local timezone. The note is never deleted or rewritten by a later day's run.

## Ontology changes

In `template/99-workflow-config/reference/ontology.md`:

- **§Meeting gains** optional `confidence` and `confidence-reasons`, and the
  closed reason vocabulary as a schema key (loaded by the guard the way
  decision `tags` were):
  - rating: `[high, medium, low]`
  - reasons: `calendar-match-high | calendar-match-medium |
    calendar-match-low | no-calendar-match | calendar-tool-unavailable`
    (one of); `entity-domain-match | calendar-subject-match |
    content-keyword-match | no-project-match` (one of);
    `all-attendees-known | new-attendees:{N}` (one of).
- **`source` becomes an enum**: `[teams, recorder, manual, email]` — the
  capture channel, not the adapter name.
- **`source-drive-id` is replaced by `source-recording-id`** (namespaced
  string). The lab retired its Drive path; the ghost does not ship.
- **`review_status` unchanged** (three values — decision 7).
- **New §Daily-note block** (sixth object type, deliberately thin):
  `required: [date, type]` · `enums: {type: [daily-note]}` ·
  `body_sections: [Recap, Meetings, End of day]`. The marker convention is
  documented in the surrounding prose. Conformance guard picks it up via
  a new harness entry (`60-daily-notes/*.md`).

## Fixture enrichment

Per the standing rule on issue #2 — fixtures move to the skills' real
output shape:

- **8 meeting notes**: `confidence` + `confidence-reasons` coherent with
  each fixture's story (the recorder brainstorm gets
  `calendar-tool-unavailable`; the `needs-attention` pair get low-
  confidence profiles); the executive (`morgan-ellery`, created by P1a)
  joins every `attendees` list — closing P1a's deliberate boundary;
  `source-recording-id` on the recorder capture; `source` enum coverage
  (`teams`, `recorder`, plus `manual`/`email` across the set).
- **3 daily notes**: rewritten to the contract above — marker-fenced recap
  and prep regions, hand-written jottings *outside* markers so the merge
  rule is exercised by real fixtures, content cross-referencing the meeting
  fixtures of those dates.
- Inbox fixtures unchanged — they are the input corpus for hand-testing.

## Verification

Local, matching CI: `lint_plugin.py` · `validate_template.py` ·
`pytest scripts/tests -q`. The two non-required jobs from P1a
(`runtime floor (python 3.10)`, `cross-platform (windows)`) cover the new
vaultlib code automatically.

New tests: `dates` (weekend rollover, gap-recap window since last note) ·
`daily-note write` merge preserves bytes outside markers exactly, and is
idempotent (second run → identical file) · `daily-note read` region
parsing · `sync scan` dedup (namespaced ids + content-hash backstop) ·
`update-queue` against the fixture vault (queue membership, metrics values,
self-check trip) · `reconcile-reviews` one-way semantics · daily-note
fixture conformance (§Daily-note `body_sections`).

Hand-test: `make_test_vault.py /tmp/loop-vault --with-plugins`, drop the
inbox fixtures, run `/sync-recordings` interactively and `/evening-sync`
end-to-end, and read tomorrow's daily note as the judged artifact. Then
jot into it by hand, re-run `/evening-sync`, and confirm the jottings
survive and surface in the recap.
